# 单项兼容记录模板

适用于更换 donor、Android API、内核、vendor/HAL 或解决真机 bug。每项记录应链接到具体提交和报告，不只写“已适配”。

## 目标与触发

- 设备/批次、目标 China ROM、实际 Android API、源代码提交/包 SHA256：
- 问题：复现步骤、错误日志的脱敏片段、此前行为：
- 证据类别：离线推断 / host 检查 / 构建 / 镜像回读 / 真机运行：

## 实现

- 生产接口：内核节点/ioctl/BPF/属性/HAL 合同与消费者：
- 修改文件、代码来源和许可证、输入 hash、实际修改理由：
- DAC、SELinux、init、VINTF、资源配置需要一起修改的项目：
- 未选择其他方案的证据；对性能、功耗、加密或回退的影响：

## 验证和边界

- 可复现的命令/工具与版本、报告路径、结果：
- 产物 SHA256、完整镜像集合或构建编号：
- 真机用例、冷启动/重启/休眠/负载回归：
- 未验证项目、已知失败、阻断可刷/稳定发布的条件：
- 撤销方法、依赖的备份和是否实际验证回退：

## 下次移植可复用部分

- 能保留的 polaris 硬件契约与测试方法：
- 换 Android/donor 后必须重审的版本、签名、ABI、策略或布局：
- 更新 `porting-handoff.md`、来源锁与 `release-gates.json`；原始设备日志和备份保留本地。
